## 한눈에 보기

- 요소는 **이동시간 · 교통 편의성 · 주거비** 3개. 각 요소는 매물별 **절대 점수(0~100)** 로 계산한다. 다른 매물에 따라 점수가 바뀌지 않는다.
- 사용자는 가중치를 직접 조절하지 않는다. **1순위·2순위만 고르면** 가중치가 정해진다: **0.55 / 0.30 / 0.15**.
- 예산은 **여유를 둔 필수 조건**: 월 고정 주거비는 예산 + 10만 원, 보증금은 예산 + 20% 넘으면 제외. → **2026-11-08 변경: 여유 없이 예산을 넘으면 제외, 점수에는 안 씀.**
- 공강은 고려하지 않는다 (공강 귀가 가능 여부는 결국 거리의 함수라 이동시간 점수와 겹치고, 실제 데이터에서 구분력도 없었다).
- 결과: 점수순 목록 + 다른 순위 조합에서는 상위 3위인 매물의 **비추천 사유** + 상위 10개 **특장점**.
- **계산은 전부 코드**, LLM은 입력 해석(시간표 사진 등)과 설명 문장만 맡는다.

### v1 대비 바뀐 점

| 항목 | v1 | v2 |
|---|---|---|
| 입력 | 시간표 + 예산 (중요도는 고급 설정) | 예산, 시간표 사진(선택), 자주 가는 곳(지도), 학과·학년, 희망 통학 시간, 1·2순위 |
| 가중치 | 고정 0.40/0.35/0.25 | 1·2순위 → 0.55/0.30/0.15 |
| 통학 점수 | 직선 (5분 100점, 25분 0점) | 희망 통학 시간 기준 **직선 + 반감기 지수 감소** |
| 공강 | 귀가 기준 이상이면 이동 추가 | **고려하지 않음** |
| 주거비 | 보증금 기회비용 포함 | 월세 + 관리비만 (보증금은 필터에만) |
| 분야별 추천 | 분야별 1위 + 기준선 30점 | 없음. 대신 다른 1·2순위 조합 기준 비추천 사유 |
| 장기 관점 | 학과 분포 × α | 학과 건물 고정 비중 (근거는 README에서 팀 의견) |

## 1. 입력

| 입력 | 필수 | 형식 | 비고 |
|---|---|---|---|
| 월 고정 주거비 예산 | ✅ | 만원 (월세 + 관리비) | |
| 보증금 예산 | 선택 | 만원 | 없으면 보증금 필터 생략 |
| 시간표 | 선택 | 사진 → `[요일, 시작, 종료, 강의동]` | 이미지 인식 후 **확인·수정 화면 필수**. 줄임말(포관 등) → 건물 목록 매핑. 직접 입력도 유지. 계약 시점엔 다음 학기 시간표가 없을 수 있어 선택 입력 |
| 자주 가는 곳 | 선택 | 지도에서 위치 선택 + 주간 횟수 + 학교에서 바로 가는지 | |
| 학과 / 학년 | ✅ / ✅ | 학과 선택 → 학과 건물 자동 채움 (수정 가능) | 여러 건물을 쓰는 학과 고려 |
| 희망 통학 시간 | ✅ | 편도 분, 스크롤 | 도보 기준임을 화면에 표시 |
| 1순위 · 2순위 | ✅ | 이동시간 / 교통 편의성 / 주거비 중 2개 | 3순위는 자동. 결과 화면에서 바꿀 수 있음 |

자연어 입력(챗봇)은 부가 기능이며 필수 입력이 아니다. 챗봇이 붙으면 자연어 → **1·2순위**로 변환한다 (가중치 숫자를 직접 만들게 하지 않는다. 근거: 참고 논문 표 1, LLM 직접 가중치 방식이 가장 낮은 정확도).

## 2. 필수 조건 (필터)

```
제외 조건:  월세 + 관리비 > 월 예산 + 10만 원
            보증금        > 보증금 예산 × 1.2        (보증금 예산을 입력한 경우)
```

- 예산 ~ 예산 + 여유 사이의 매물: 추천에 포함, **"예산 초과" 표시**, 주거비 점수 0점. → **2026-11-08 변경: 여유 0, 예산 초과 구간 없음.**
- 관리비가 없는 매물: 데이터 확보 후 결정 (보류).
- 필터로 빠진 매물도 사유를 남긴다. 예: "예산보다 월 12만 원 비싸서 제외".

## 3. 시간 점수 함수 (공통)

이동시간과 교통 편의성의 모든 부분에 같은 모양의 함수를 쓴다.

```
score(t; T, h) = 100 − 15 × t / T              (t ≤ T)   희망 시간 안: 완만한 직선
               = 85 × 2^(−(t − T) / h)          (t > T)   희망 시간 밖: 반감기 h 지수 감소

t: 편도 시간(분), T: 기준 시간, h: 반감기(분). 0분 = 100점, T분 = 85점.
```

- 희망 시간 안에서도 **가까울수록 점수가 높다** (T = 15분이면 1분에 1점씩).
- 희망 시간을 넘으면 **h분마다 점수가 절반**이 된다. 희망 시간 안보다 점수 변화가 훨씬 크다.
- T 에서 항상 85점이라, 사용자마다 희망 시간이 달라도 "희망 시간 = 85점"의 의미가 같다.
- 0점에 가까워지기만 하고 0이 되지는 않는다.

T = 15분, h = 10분일 때:

| 편도 | 0 | 5 | 10 | **15** | 20 | 25 | 30 | 45 | 60 |
|---|---|---|---|---|---|---|---|---|---|
| 점수 | 100 | 95 | 90 | **85** | 60 | 43 | 30 | 11 | 4 |

## 4. 요소별 점수

### 4.1 이동시간

```
이동시간 점수 = 0.4 × 학과 건물 점수 + 0.4 × 자주 가는 곳 점수 + 0.2 × 시간표 점수
```

부분별로 **편도 평균(분)** 을 먼저 구하고, 3장의 함수로 점수화한 다음 합친다. (횟수를 그대로 더하면 반영 정도를 중요도가 아니라 횟수가 정해 버리기 때문.)

| 부분 | 편도 평균 계산 | T | h | 이동 수단 |
|---|---|---|---|---|
| 학과 건물 | 매물 ↔ 학과 건물 (여러 건물이면 평균) | 희망 통학 시간 | 10 | 도보 |
| 자주 가는 곳 | 장소별 편도를 주간 횟수로 가중 평균. 학교에서 바로 가는 곳은 장소 → 집 편도만 | 20 | 15 | 도보 15분 이하면 도보, 넘으면 min(도보, 대중교통 추정) |
| 시간표 | 요일마다 집 → 첫 수업 건물, 마지막 수업 건물 → 집. 수업 사이 이동은 제외 | 희망 통학 시간 | 10 | 도보 |

- 입력이 없는 부분(시간표 없음, 자주 가는 곳 없음)의 비중은 나머지 부분에 비율대로 나눈다.
- **학과 건물 두 번 반영**: 시간표에 학과 건물 수업이 있으면 학과 건물이 두 부분에 모두 들어가 실제 비중이 0.4보다 커진다. 의도("학과 건물 더 반영")와 같은 방향이라 MVP에서는 그대로 둔다 → README에서 팀 의견 요청.
- 학년은 입력받지만 MVP에서는 학과 건물 비중을 0.4로 고정한다. 학년별 조정은 README에서 팀 의견 요청.

#### 대중교통 시간 추정 (방법 A)

```
대중교통 추정 = 매물 → 가장 가까운 지하철역 도보
             + 역 사이 지하철 소요시간 (공공데이터)
             + 환승 보정 (환승 1회당 초기값 5분)
             + 대기 보정 (초기값 3분)
             + 도착역 → 장소 도보
```

- 매물 쪽(매물 → 역)은 매물마다 한 번만 계산해 저장, 장소 쪽(역 → 장소)은 장소마다 한 번만 계산한다. 추천 한 번에 ODsay 호출 0건.
- ODsay를 쓰지 않는 이유: 무료 Basic은 하루 30건이고, 지도에서 고른 장소는 미리 계산할 수 없어 추천 한 번에 "매물 수 × 장소 수"만큼 호출해야 한다. 유료 Flex는 건당 25원. 결과 저장도 사전 협의가 필요하다.
- **한계: 버스가 더 빠른 경우를 놓친다.** 추정값은 실제보다 길게 나오기만 한다(짧게 나오지는 않는다). → README에 명시.
- 검증: 대표 사례 10개 정도를 지도 앱으로 직접 확인해서, 추정과 실제의 차이를 README와 발표에 적는다.

### 4.2 교통 편의성

```
교통 편의성 점수 = score(가장 가까운 지하철역까지 도보시간; T = 5, h = 5)
```

- 역할: **입력하지 않은 곳(본가, 약속 장소 등)에 가기 편한가.** 이동시간(입력한 곳)과 일부 겹치지만 역세권을 강조하는 의도된 설계다.
- 버스정류장은 보류. 이대 주변은 대부분 역이 가까워 매물 간 차이가 작을 수 있으므로 데이터를 채운 뒤 확인한다.
- 데이터: 카카오 카테고리 검색(지하철역 `SW8`) + 도보 경로. 오프라인 스크립트로 미리 계산해 매물 열로 저장(`subway_name`, `subway_walk_min`).

### 4.3 주거비

```
월 고정 주거비 = 월세 + 관리비
주거비 점수   = 100 × (예산 − 월 고정 주거비) ÷ (예산 × 0.4)     → 0~100 사이로 자름
```

→ **2026-11-08 변경:** `주거비 점수 = 100 × (최고 − 월 고정 주거비) ÷ (최고 − 최저)`, 최고·최저는 필터를 통과한 매물의 월 고정 주거비. 예산은 쓰지 않는다. 주거비만 절대 점수가 아니다.

(이전) 예산의 60% 이하면 100점, 예산과 같으면 0점, 여유 구간(예산 초과)도 0점. 돈은 1만 원 차이가 어느 구간에서나 비슷하게 느껴지므로 직선을 쓴다. 보증금은 점수에 넣지 않고 특장점 설명에서 쓴다.

## 5. 종합 점수

```
종합 점수 = 0.55 × (1순위 요소 점수) + 0.30 × (2순위 요소 점수) + 0.15 × (3순위 요소 점수)
```

- 1·2순위 조합은 6가지. 요소별 점수는 그대로이고 가중치만 바뀌므로 결과 화면에서 순위를 바꾸면 바로 다시 정렬된다.
- 동점이면 매물 ID 순.

## 6. 결과 표시

| 구역 | 내용 |
|---|---|
| 추천 목록 | 종합 점수순. 몇 개까지 보여줄지는 미정 (임시 50개) |
| 비추천 사유 | **다른 5가지 조합 중 어디서든 상위 3위 안**인데 지금 화면에 없는 매물, 최대 3개 |
| 특장점 | 상위 10개 매물. 요소 기반 사실("10개 중 가장 저렴", "공과대학까지 3분")은 MVP, 점수에 없는 정보("편의점이 가장 가까움")는 데이터 확보 후 |
| 계산 가정 | 사용한 T, h, 가중치, 여유 금액 등을 `assumptions`로 함께 반환 |

**비추천 사유 만드는 법**: 지금 1위 매물과 비교해서 가중 점수 차이가 가장 큰 요소를 사유로 쓴다.
예) "가장 저렴하지만 학과 건물까지 편도 26분이라 희망 통학 시간(15분)보다 11분 길어요."
숫자와 사유는 코드가 만들고, LLM은 문장만 다듬는다. 다른 매물과 비교하는 문장은 설명에서는 써도 된다 (점수만 절대 점수면 된다).

| 항목 | 초기값 |
|---|---|
| 월 예산 여유 | ~~+10만 원~~ → 0 (2026-11-08) |
| 보증금 예산 여유 | ~~+20%~~ → 0 (2026-11-08) |
| 희망 시간 지점 점수 | 85점 |
| 학과 건물 · 시간표 반감기 | 10분 |
| 자주 가는 곳 T / 반감기 | 20분 / 15분 |
| 도보 → 대중교통 비교 기준 | 도보 15분 초과 |
| 환승 보정 / 대기 보정 | 5분 / 3분 |
| 지하철역 T / 반감기 | 5분 / 5분 |
| 이동시간 내부 비중 | 학과 0.4 / 자주 가는 곳 0.4 / 시간표 0.2 |
| 주거비 100점 기준 | ~~예산의 60% 이하~~ → 필터 통과 매물 중 가장 싼 매물 (2026-11-08) |
| 1·2·3순위 가중치 | 0.55 / 0.30 / 0.15 |
| 비추천 사유 기준 | 다른 조합 상위 3위, 최대 3개 |

## 9. README에 넣을 내용

**팀 의견 요청**
1. 학과 건물을 이동시간에서 40%로 크게 반영하는 근거: 학기마다 시간표가 바뀌어 학과 건물이 장기적으로 더 중요하다고 봤다. 실제로 학과 건물 수업이 많은지 확인이 필요하다 (특히 1학년은 전공 수업이 적다). 수강편람으로 확인하거나 학년별로 비중을 바꾸는 안에 대한 의견.
2. 시간표에 학과 건물 수업이 있으면 학과 건물이 두 번 반영된다. 의도와 같은 방향이라 그대로 두었는데 괜찮은지.

**알려진 한계**
1. 대중교통 시간은 지하철 기준 추정값이다. 버스가 더 빠른 경우를 놓치며, 추정값은 실제보다 길게만 나온다 (비용 때문에 ODsay를 쓰지 않음).
2. 관리비 정보가 없는 매물의 처리 방식은 미정.

## 10. 구현 순서

| 순서 | 작업 | 형태 |
|---|---|---|
| 1 | 설정 파일 + 시간 점수 함수 `score(t, T, h)` | 순수 함수 + pytest |
| 2 | 예산 필터 + 주거비 점수 | 순수 함수 + pytest |
| 3 | 이동시간: 학과 건물 · 시간표 부분 (도보) | 순수 함수 + pytest |
| 4 | 종합 점수 + 1·2순위 가중치 + 비추천 사유 | 순수 함수 + pytest |
| 5 | `POST /recommend` 입력·출력 교체 | FastAPI |
| 6 | 좌표 채우기 → 지하철역 도보시간 → 교통 편의성 | 오프라인 스크립트 |
| 7 | 자주 가는 곳 + 대중교통 추정 (역간 소요시간 데이터) | 스크립트 + 함수 |
| 8 | 특장점 생성, 시간표 이미지 인식 | 함수 + LLM |

1~5는 지금 데이터(강의동 4개 도보시간, 월세·관리비)로 바로 만들고 테스트할 수 있다.
